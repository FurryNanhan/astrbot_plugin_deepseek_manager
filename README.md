# DeepSeek 账户管家 (astrbot_plugin_deepseek_manager)

一个基于 AstrBot 的终极查询插件。支持一键查询 DeepSeek 账户余额、历史 Token 用量与消费金额。

> **声明**：本插件的核心代码由 DeepSeek AI 辅助生成，经人工调试与整理，仅供学习交流使用。

---

## ✨ 双模式架构（必读）

本插件采用 **“安全与进阶分离”** 的设计，您可以根据自身需求自由选择配置：

*   🌟 **基础模式（100% 官方安全）**：仅填入官方 `API Key`（`sk-` 开头）。可使用 `/ds balance` 查余额，无任何风控风险。
*   🔥 **进阶模式（存在极低概率风控）**：填入网页端 `userToken`。可使用 `/ds usage`、`/ds cost` 和 `/ds all` 深度查账。数据来源于模拟网页端请求的内部接口。

---

## 🚀 指令大全（仅管理员可用）

所有指令均基于 `/ds` 指令组：

| 指令 | 说明 | 所需配置 |
| :--- | :--- | :--- |
| `/ds balance` | 查询账户余额（总余额、充值余额） | API Key |
| `/ds usage [参数]` | 查询 Token 用量（输入/输出/请求次数） | userToken |
| `/ds cost [参数]` | 查询消费金额（人民币/美元） | userToken |
| `/ds all [参数]` | 一键查询余额、用量和消费金额 | API Key + userToken |
| `/ds help` | 查看帮助面板 | 无 |

### ⏱️ 智能时间参数解析
`[参数]` 支持极其自由的输入方式：
- **留空**：查询配置项中的默认天数（默认 30 天）。
- **纯数字**：如 `/ds usage 7`，查询最近 7 天。
- **快捷词**：如 `/ds usage today`（今天），`/ds usage month`（本月）。
- **日期范围**：如 `/ds usage 10.01 10.31` 或 `10-01 10-31`（支持 `.` 和 `-` 分割，**自动识别跨年**）。

## 📦 安装与配置

1. 将本插件放入 AstrBot 的 `data/plugins/` 目录。
2. 在 WebUI 中重载插件。
3. 在 WebUI 的插件配置页面填写您的凭证：

| 配置项 | 类型 | 说明 |
| :--- | :--- | :--- |
| `deepseek_api_key` | string | 官方 API Key（仅用于余额查询） |
| `deepseek_user_token` | string | 网页端 Token（用于用量和消费查询） |
| `default_days` | int | 默认查询天数（1/7/15/30） |
| `number_format` | string | 数字展示格式（comma: 1,000,000 / short: 1.00M） |
| `request_timeout` | int | 请求超时时间（秒），默认 10。若经常查询半年以上的跨度，建议调至 30 或 60 |

## 🔑 如何获取凭证？

### 1. 获取官方 API Key（基础模式）
1. 登录 [platform.deepseek.com](https://platform.deepseek.com)。
2. 点击左侧 **API keys**，点击 **创建 API key**。
3. 复制生成的 `sk-` 开头的字符串，填入插件配置的 `deepseek_api_key`。

### 2. 获取网页端 userToken（进阶模式）

进阶模式需要调用网页端接口，必须抓取您的登录凭证。**强烈推荐使用“方法一”，成功率最高且最不容易出错。**

> 💡 **防呆提示**：无论您使用哪种方法，插件代码已经自带了“超级清洗”功能。如果您不小心把 `Bearer ` 前缀、甚至 `userToken=` 连等号都一起复制进去了，代码也会自动识别并提取出真正的 Token。所以请放心复制。

**方法一：从 Local Storage 获取（⭐ 最推荐，最精确）**
1. 登录 [platform.deepseek.com](https://platform.deepseek.com)。
2. 按 `F12` 打开开发者工具。
3. 在上方标签栏找到并点击 **`Application`（应用/应用程序）**。
4. 在左侧展开 **`Local Storage`（本地存储）**，点击下方的 `https://platform.deepseek.com`。
5. 在右侧的列表中，找到名称为 **`userToken`** 的那一行。
6. **只复制右侧 `Value` 列里的一长串字符**，**千万不要**把 `userToken` 这个词也复制进去。

**方法二：从网络请求获取（备用方案）**
1. 按 `F12` 打开开发者工具，切换到 **`Network`（网络）** 标签页。
2. 刷新一下网页，在请求列表里找到名字带有 **`amount`** 或 **`cost`** 的请求，点击它。
3. 在右侧的 **`Headers`（标头）** 面板中，向下滚动找到 **`Request Headers`（请求标头）**。
4. 找到 `Authorization` 字段，它的值通常是 `Bearer eyJhb...`。
5. **复制 `Bearer ` 后面的那一长串字符**（只要后面的部分，前面的 Bearer 可以不用复制，代码会自动兼容）。

## ⚠️ 进阶模式深度警告（宇宙级免责声明）

使用 `userToken` 查询用量和消费时，**请务必阅读以下 15 条条款**：

1. **【接口性质声明】** `/ds usage` 和 `/ds cost` 是通过模拟网页端请求，调用 `platform.deepseek.com` 的内部私有接口。**这并非官方公开 API**，官方随时可能修改接口结构、增加 Cloudflare 验证或彻底废弃该接口，届时插件将失效，需等待作者更新。

2. **【封号与风控风险】** 请**绝对不要**将本插件绑定到定时任务或进行高频自动化查询！过度请求极易触发 DeepSeek 账号风控。**因使用不当导致的 API Key 被限流、账号被限制登录或封禁，需由使用者自行承担全部后果。**

3. **【内置防封机制】** 考虑到上述风险，插件代码底层已强制内置 `0.5s` 的请求延迟，并在超过 90 天的长跨度查询时进行切片累加。但这只能降低风险，不能完全免疫。

4. **【数据隐私保护】** 您的 `userToken` 和 `API Key` 仅保存在本地 AstrBot 配置文件中（均已标记为 `secret` 隐藏），插件仅在本地直接向官方服务器发起请求，**绝无任何第三方数据外传**。请务必保管好您的配置文件，勿将 Token 截图发到公开群聊。

5. **【数据延迟声明】** 官方网页端接口的数据并非完全实时，通常存在几分钟到几十分钟的延迟。如果您刚刚调用完 API 立刻查用量，可能无法立刻显示最新消耗。

6. **【统计范围限制】** 本插件统计的数据**仅包含通过 API（API Key）产生的消耗**。**不包含**您在 DeepSeek 官方网页版（chat.deepseek.com）进行免费对话所消耗的额度。

7. **【Token 计费口径】** 报告中的“输入 Token”包含了缓存命中和未命中两部分。由于 DeepSeek 对“缓存命中”的计费极低，因此您看到的上亿 Token 消耗，实际扣费可能非常少，请勿因此恐慌。

8. **【消费金额误差】** `/ds cost` 查出的消费金额仅供参考。受官方计费延迟、汇率浮动、赠金抵扣规则影响，最终扣费请以 DeepSeek 官方控制台出具的真实账单为准。

9. **【多 Key 混合统计】** 目前插件的用量和消费是**按整个账号汇总**的。如果您账号下创建了多个不同的 API Key（例如分发给不同应用），插件无法区分具体是哪个 Key 消耗的。

10. **【模型代号差异】** 插件展示的模型列表（如 `deepseek-v4-flash`）为官方底层记录的代号，可能与您在网页端看到的最新版本展示名称存在细微差异，但不影响总量统计。

11. **【查询保护机制】** 受官方单次最多 31 天的限制，当查询跨度超 90 天时，插件会在后台自动按 30 天切片请求。此时机器人会等待 5~15 秒，**请勿在等待期间疯狂重复发送指令**，否则极易触发风控。

12. **【并发冲突限制】** 如果您在一个群里同时艾特机器人执行多个 `/ds` 指令，后发起的请求可能会因为等待超时而失败。建议等待上一次查询出结果后再试。

13. **【网络环境要求】** 运行 AstrBot 的服务器必须能够顺畅访问 `api.deepseek.com` 与 `platform.deepseek.com`。若您的服务器处于严格的网络限制环境中（如部分国内云服务器），可能无法获取数据。

14. **【配置生效提示】** 在 WebUI 修改了 Token 或默认天数后，请务必点击“重载插件”或重启 AstrBot，否则旧配置仍会生效在内存中。

## ❓ 常见问题 (FAQ)

**Q: 为什么 `/ds balance` 提示我配置 API Key？**
A: 余额查询走的是纯正的官方接口，必须填写 `sk-` 开头的 API Key。

**Q: 为什么 `/ds usage` 查出来是 0？**
A: 请确认您填入的是 `userToken` 而非 API Key；另外，如果您近期确实没有通过 API 调用过模型，或者时间范围选错了，也会显示为 0。

**Q: 为什么我查了 1 年，等了很久还报错？**
A: 跨度过大时，DeepSeek 官方接口会拦截。代码会自动切片，如果网络不佳或超时（配置项 `request_timeout` 默认 10 秒），可能会报错。建议缩小查询范围。

**Q: 为什么以前能查，今天突然提示“userToken 无效或已过期”？**
A: 网页端的 `userToken` 是有有效期的（通常几天到几周不等）。过期后，您只需按照上面的教程重新去 F12 抓取一次最新的 Token 填进来即可，无需重新安装插件。
